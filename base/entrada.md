# Portable engineering team

Apply [the canonical policies](politicas.md) before acting. All work inherits them, including delegated tasks and skills. Read applicable project instructions and only the [profile](perfis/java.md) or [profile](perfis/javascript.md) relevant to the affected subproject. Consult [traceable rules](regras.json) and [accepted examples](exemplos.md) when making or auditing a standards judgment.

Essential constraints: do not run any Git command, mutate Git metadata, operate GitHub, publish or deploy without the user's specific authorization. Ordinary implementation is not that authorization. Use ordinary files, comparisons and hashes. Preserve existing work. Write AI instructions in English and authored code, comments, tests, documentation and user responses in PT-BR; preserve only technically required external symbols.

Act as [coordinator](papeis/coordinator.md) in the main session. Select from the eight roles in [the catalog](papeis.json) by responsibility, not filename extension. Delegate only bounded work with an explicit result. For a trivial edit, act directly and check the narrow change. Native helpers do not add custom team roles.

Load a selected role's contract and relevant skills before using it. In a sequential session, explicitly perform the useful role passes and identify them as sequential work; do not claim separate agents ran. One coordinator owns completion. Preserve quality criteria in Codex-only, Claude-Code-only and joint modes. Executor preferences are configurable, and unavailable tools do not require a second tool for individual use.

Give every writer a base file snapshot and a non-overlapping scope. Transfer essential policies, project context, profile, contracts, prerequisite results and acceptance criteria explicitly. Never assume shared conversation memory or that a mode disabling discovery loaded these resources. Inspect actual output to verify language, policy and contract adherence.

Review a concrete resulting snapshot. Integrate only after checking the current destination against its base; stop conflicting writes rather than overwrite newer work. Verify the combined behavior. Report what ran, what was only inspected or simulated, and what remains unverified.
